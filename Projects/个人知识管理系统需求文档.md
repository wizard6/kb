# 个人知识管理系统 — 需求文档

> 基于与 Kun 的交互过程梳理，记录已建立的工作模式、约束和未来方向。

## 1. 系统概述

### 1.1 定位

一套以个人笔记为中心的知识管理系统，基于 PARA 方法组织内容，通过 Obsidian 提供编辑和浏览体验，通过 Kun（AI 助手）实现自动化写入和索引维护。

### 1.2 架构

```
┌─ 工作区 (default_workspace) ───────────────┐
│  knowledge-base/                            │
│  ├─ _index.md          ← 全局索引           │
│  ├─ _guard.md          ← 安全与操作公约      │
│  ├─ _hooks/            ← 自动化脚本          │
│  ├─ Projects/          ← 有期限的任务        │
│  ├─ Areas/             ← 长期负责的领域      │
│  ├─ Resources/         ← 兴趣/参考素材       │
│  └─ Archives/          ← 已完结归档          │
├─────────────────────────────────────────────┤
│             ↕ 双向同步 (sync-obsidian.ps1)   │
├─ Obsidian Vault ────────────────────────────┤
│  deepseek-kb/ (同上结构)                     │
└─────────────────────────────────────────────┘
```

### 1.3 核心角色

| 角色 | 职责 | 工具 |
|------|------|------|
| **用户** | 提供内容、审阅、浏览编辑 | Obsidian + 对话输入 |
| **Kun (AI)** | 写入条目、更新索引、分析项目、维护同步 | 文件操作 + 同步脚本 |

## 2. 知识库操作规范

### 2.1 写入规则

- **保持原文**：写入新条目时不得添加解释、阐述、注释，仅保留用户原始表述
- **价值判断**：写入前必须评估内容的知识价值
- **格式**：Markdown + YAML frontmatter（title / created / tags / source / status / para）

### 2.2 价值判断标准

✅ 值得写入：
- 独特的看法、见解、角度
- 用户的个人数据、关注焦点
- 经典名句、需要聚焦的词条

❌ 不值得写入：
- 百科式词条解释（到处能查到的定义）
- 常见常识（非用户独有视角）

### 2.3 红线规则（禁止 AI 自动执行）

| 操作 | 约束 |
|------|------|
| 删除文件 | 必须用户明确确认 |
| 删除目录 | 必须用户明确确认 |
| 移动/重命名 | 必须用户明确确认 |
| 清空/覆盖内容（>50%） | 需用户确认 |

### 2.4 删除审批流程

读取 _guard.md → 告知用户 → 列出清单 → request_user_input 二次确认 → 执行/放弃

## 3. 已建立的工作流

### 3.1 知识条目写入

```
用户提出写入请求
  → Kun 评估知识价值（是否符合写入标准）
    → 符合：创建 .md 文件 + 写入原文（不加注释）
    → 不符合：跳过，说明理由
  → 更新 _index.md 索引
  → 同步到 Obsidian vault
```

### 3.2 Obsidian 双向同步

```
工作区知识库 ←──→ sync-obsidian.ps1 ──→ Obsidian vault

push:  工作区 → Obsidian（默认方向，Kun 写入后自动触发）
pull:  Obsidian → 工作区（用户在 Obsidian 中编辑后拉回）
full:  先 pull 再 push（完整双向同步）
```

### 3.3 外部项目分析

```
用户提供项目路径
  → Kun 全面分析（技术栈 / 架构 / 数据模型 / API / 状态）
  → 写入 Resources/ 作为参考条目
  → 更新索引 + 同步到 Obsidian
```

### 3.4 钩子脚本

`_hooks/` 目录存放自动化脚本：
- `sync-obsidian.ps1` — 双向同步
- `pre-delete.ps1` — 删除操作安全检查

## 4. AI 交互偏好

### 4.1 回答风格

- 清晰直接，不添加冗余修饰
- 用户说中文即用中文回答
- 不擅自解读或展开用户的表述

### 4.2 操作原则

- 先读取当前状态再行动
- 小范围精准修改，不搞大规模重写
- 工具可用的场景不空口描述

### 4.3 能力边界（参考 Kun 能力清单）

| 领域 | 能力 |
|------|------|
| 文件操作 | 读/写/编辑/搜索/grep/find |
| 知识库 | 写入条目/更新索引/Obsidian 同步 |
| 项目分析 | 分析外部代码项目并记录 |
| 网页 | 网页抓取/浏览器控制 |
| 调度 | 定时任务/工作流 |
| 记忆 | 创建/更新/删除用户偏好 |
