# NovelWizard 会话链路节点模板

> 定义「一个节点长什么样」——结构、行为、输入输出、决策规则。
> 任何符合此模板的节点都可以被工作流引擎加载和执行。

---

## 一、节点定义模板

### 1.1 完整结构

```typescript
interface NodeDefinition {
  // ── 身份 ──
  id: string;                    // 唯一标识，如 "parse-inspiration"
  name: string;                  // 显示名，如 "解析灵感"
  description: string;           // 一句话说明这个节点做什么
  icon?: string;                 // 可视化编辑器中显示的图标

  // ── 类型 ──
  kind: NodeKind;                // 节点类型（见 1.2）
  composite?: boolean;           // 是否为复合节点

  // ── 配置 ──
  config: NodeConfig;            // 节点的参数配置（见 1.3）

  // ── 接口 ──
  inputs: Port[];                // 输入端口（见 2.1）
  outputs: Port[];               // 输出端口（见 2.2）

  // ── 路由 ──
  nextOptions: NextOption[];     // 可选下一跳列表（见 3.1）
  selectionRules: SelectionRule[]; // 内置选择规则（见 3.2）

  // ── 子图（仅 composite）──
  subGraph?: SubGraphDefinition; // 复合节点的内部子图

  // ── 错误处理 ──
  errorHandler?: ErrorHandler;   // 节点执行出错时的行为
}
```

### 1.2 节点类型（NodeKind）

```typescript
type NodeKind =
  // ── AI 类 ──
  | 'ai-call'              // 调用 LLM
  | 'ai-stream'            // 流式调用 LLM
  | 'skill-exec'           // 调用已注册的 Skill

  // ── 人类类 ──
  | 'human-decision'       // 暂停，等用户选择
  | 'human-input'          // 暂停，等用户输入文本

  // ── 流程类 ──
  | 'condition'            // 条件判断（if/else）
  | 'loop'                 // 循环
  | 'transform'            // 数据变换（无 AI）
  | 'merge'                // 并行分支汇聚

  // ── 复合类 ──
  | 'composite'            // 复合节点（含子图）
  | 'reference'            // 引用另一个流程作为子流程
```

### 1.3 节点配置（NodeConfig）

每种节点类型有自己的配置结构：

```typescript
type NodeConfig =
  | AiCallConfig
  | AiStreamConfig
  | SkillExecConfig
  | HumanDecisionConfig
  | HumanInputConfig
  | ConditionConfig
  | LoopConfig
  | TransformConfig
  | MergeConfig
  | CompositeConfig;

// ── AI 调用 ──
interface AiCallConfig {
  systemPrompt: string;            // system prompt 模板
  model?: string;                  // 可选，覆盖默认模型
  temperature?: number;            // 可选，覆盖默认温度
  maxTokens?: number;
  responseSchema?: Record<string, unknown>;  // 期望的输出结构
}

// ── Skill 执行 ──
interface SkillExecConfig {
  skillId: string;                 // 要调用的 Skill ID
  params?: Record<string, unknown>; // 固定参数
  mockable?: boolean;              // 是否允许 mock
}

// ── 人类决策 ──
interface HumanDecisionConfig {
  question: string;                // 向用户展示的问题
  options: HumanOption[];          // 选项列表
  allowCustom?: boolean;           // 是否允许用户自由输入
  timeout?: number;                // 超时（秒），超时后走默认
}

interface HumanOption {
  label: string;                   // 选项显示名
  value: string;                   // 选项值
  description?: string;            // 选项说明
  default?: boolean;               // 是否默认
}

// ── 人类输入 ──
interface HumanInputConfig {
  prompt: string;                  // 向用户展示的输入提示
  placeholder?: string;            // 输入框占位符
  multiline?: boolean;             // 是否多行输入
}

// ── 条件判断 ──
interface ConditionConfig {
  expression: string;              // 条件表达式
  description?: string;            // 人类可读的条件说明
}

// ── 循环 ──
interface LoopConfig {
  maxIterations: number;           // 最大循环次数
  exitCondition?: string;          // 提前退出条件
}

// ── 数据变换 ──
interface TransformConfig {
  transformType: 'map' | 'filter' | 'aggregate' | 'format' | 'custom';
  mapping?: Record<string, string>; // 字段映射
  template?: string;               // 输出模板
}

// ── 汇聚 ──
interface MergeConfig {
  strategy: 'wait-all' | 'wait-any' | 'wait-n';
  waitCount?: number;              // wait-n 时的等待数量
  mergeMode: 'concat' | 'combine' | 'pick-first';
}

// ── 复合 ──
interface CompositeConfig {
  subFlowId: string;               // 子流程 ID
  passContext: boolean;            // 是否传递上下文
}
```

## 三、路由定义

### 3.1 可选下一跳（NextOption）

每个节点决定自己能去哪些节点：

```typescript
interface NextOption {
  targetNodeId: string;            // 目标节点 ID
  label: string;                   // 选项显示名，如「完整度够→扩写」
  condition?: string;              // 建议条件（自然语言描述）
                                   // 示例: "当 completeness > 80% 时优先走此路"
  parallel?: boolean;              // 是否并行执行
  description?: string;            // 补充说明，供 AI 决策参考
}
```

### 3.2 选择规则（SelectionRule）

AI 在可选列表中决策时的约束：

```typescript
interface SelectionRule {
  type: 'prefer' | 'avoid' | 'require' | 'forbid';
  target: string;                  // 目标节点 ID 或标签
  condition?: string;              // 触发条件（自然语言描述）
  priority?: number;               // 优先级（数字越大越优先）
  reason?: string;                 // 为什么有这个规则（人类可读）
}
```

| 类型 | 含义 | 示例 |
|------|------|------|
| `prefer` | 条件满足时优先选 | `completeness < 80% 时优先走「追问」` |
| `avoid` | 条件满足时尽量避免 | `用户明确说「跳过」时避免走「追问」` |
| `require` | 条件满足时强制选 | `种子为 null 时必须走「解析灵感」` |
| `forbid` | 条件满足时禁止选 | `已完成时禁止走「解析灵感」` |

### 3.3 错误处理

```typescript
interface ErrorHandler {
  onError: 'retry' | 'fallback' | 'fail' | 'human-intervene';
  maxRetries?: number;             // retry 时的最大重试次数
  retryDelay?: number;             // 重试间隔（毫秒）
  fallbackNodeId?: string;         // fallback 时跳到哪个节点
  errorMessage?: string;           // fail 时展示的错误信息
}
```

## 四、完整示例

### 4.1 原子节点示例：「解析灵感」

```typescript
const parseInspirationNode: NodeDefinition = {
  id: 'parse-inspiration',
  name: '解析灵感',
  description: '将用户输入的原始灵感文本解析为结构化世界种子',
  kind: 'skill-exec',
  icon: '🔍',

  config: {
    skillId: 'inspiration-parse',
    mockable: true,
  },

  inputs: [
    { name: 'rawText', type: 'string', description: '用户输入的原始灵感', required: true },
    { name: 'existingSeed', type: 'WorldSeed', description: '已有种子（追加解析时）', required: false },
  ],

  outputs: [
    { name: 'seed', type: 'WorldSeed', description: '解析后的结构化种子', required: true },
    { name: 'completeness', type: 'number', description: '完整度评分 0-100', required: true },
    { name: 'missingFields', type: 'string[]', description: '缺失的字段列表', required: false },
  ],

  nextOptions: [
    {
      targetNodeId: 'expand-world',
      label: '完善世界观 → 扩写',
      condition: 'completeness >= 60 && user wants expansion',
    },
    {
      targetNodeId: 'ask-missing',
      label: '追问缺失信息',
      condition: 'completeness < 60 || has critical missing fields',
    },
    {
      targetNodeId: 'complete-done',
      label: '直接完成',
      condition: 'user explicitly says "done" or skips',
    },
  ],

  selectionRules: [
    {
      type: 'prefer',
      target: 'ask-missing',
      condition: 'completeness < 60',
      priority: 10,
      reason: '完整度低于 60% 时先补齐信息再往后走',
    },
    {
      type: 'forbid',
      target: 'expand-world',
      condition: 'seed.title is empty || seed.setting is empty',
      reason: '没有核心设定之前不能扩写世界观',
    },
  ],
};
```

        outputs: [{ name: 'intent', type: 'json', required: true }],
        nextOptions: [{ targetNodeId: 'route' }],
        selectionRules: [],
      },
      {
        id: 'route',
        name: '路由',
        kind: 'condition',
        config: { expression: 'intent.type' },
        inputs: [{ name: 'intent', type: 'json', required: true }],
        outputs: [{ name: 'route', type: 'string', required: true }],
        nextOptions: [
          { targetNodeId: 'exec-skill', condition: 'intent.type === "skill"' },

## 五、节点注册接口

### 5.1 NodeHandler（执行器）

```typescript
interface NodeHandler {
  kind: NodeKind;
  execute(context: ExecutionContext): Promise<ExecutionResult>;
}

interface ExecutionContext {
  node: NodeDefinition;
  inputs: Record<string, unknown>;   // 从输入端口获取的值
  state: Record<string, unknown>;    // 流程运行时状态
  signal: AbortSignal;               // 取消信号
  // 运行时能力
  llm: {
    call(params: LlmParams): Promise<LlmResult>;
    stream(params: LlmParams): AsyncIterable<LlmResult>;
  };
  skills: {
    execute(skillId: string, params: unknown): Promise<unknown>;
  };
  logger: {
    info(msg: string, data?: unknown): void;
    warn(msg: string, data?: unknown): void;
    error(msg: string, data?: unknown): void;
  };
}

interface ExecutionResult {
  outputs: Record<string, unknown>;  // 输出端口的值
  status: 'success' | 'failed' | 'paused';
  error?: string;
}
```

### 5.2 NodeTypeRegistry（注册表）

```typescript
interface NodeTypeRegistration {
  kind: NodeKind;
  label: string;
  description: string;
  category: 'ai' | 'human' | 'skill' | 'flow' | 'data';
  handler: NodeHandler;
  // 可视化编辑器配置面板
  configSchema: Record<string, unknown>;  // Zod schema
  defaultConfig: Record<string, unknown>;
  // 默认端口
  defaultInputs: Port[];
  defaultOutputs: Port[];
}
```

## 六、模板使用说明

### 6.1 新建节点步骤

```
① 确定节点类型（NodeKind）
  → ai-call / skill-exec / human-decision / condition / transform / ...

② 编写 NodeDefinition
  → id / name / description / kind / config
  → inputs / outputs
  → nextOptions / selectionRules

③ 注册节点类型（如果引擎还没有）
  → NodeTypeRegistry.register({ kind, handler, configSchema, ... })

④ 编写 handler（如果引擎还没有）
  → 实现 NodeHandler.execute()

⑤ 将节点加入流程定义
  → FlowDefinition.nodes.push(node)
  → 在父节点的 nextOptions 中引用此节点
```

### 6.2 约束

| 约束 | 说明 |
|------|------|
| ❌ 节点不能自己决定执行顺序 | 由 AI 在 `nextOptions` 中选 |
| ❌ 节点不能访问外部系统 | 所有能力通过 `ExecutionContext` 注入 |
| ❌ 节点不能直接读写 DB | 通过 Skill 或 transform 间接操作 |
| ✅ 节点可以异步执行 | handler 返回 Promise |
| ✅ 节点可以暂停 | 返回 `status: 'paused'`，等待人类介入后继续 |

### 6.4 Skill 节点 vs 硬编码节点

并非所有节点都应该是 Skill。引擎内置 9 个稳定节点，其余才是 Skill。

#### 引擎内置节点（硬编码，稳定不变）

| 节点 | 用途 | 为什么硬编码 |
|------|------|-------------|
| `ai-call` | 调用 LLM | 任何 AI 应用都需要，跨领域通用 |
| `skill-exec` | 调用 Skill | Skill 系统的调度入口，引擎核心 |
| `human-decision` | 暂停等用户选择 | 任何 AI 应用都需要人类介入 |
| `human-input` | 暂停等用户输入 | 同上 |
| `condition` | 条件判断 | 通用流程控制 |
| `loop` | 循环 | 通用流程控制 |
| `transform` | 数据变换 | 通用数据操作 |
| `merge` | 并行分支汇聚 | 通用流程控制 |
| `composite` | 子流程组合 | 复合节点的容器 |

这 9 个节点不通过 Skill 系统注册，直接内置在引擎中。它们不依赖任何领域代码。

#### Skill 节点（可插拔，业务相关）

| 节点 | 用途 | 为什么是 Skill |
|------|------|---------------|
| `inspiration-parse` | 解析灵感 | 小说创作领域特有 |
| `inspiration-expand` | 扩写世界观 | 小说创作领域特有 |
| `inspiration-completeness` | 完整度评估 | 小说创作领域特有 |
| `chapter-outline` | 章节大纲 | 小说创作领域特有 |

判断标准：**换一个 AI 应用，这个节点还能不能用？**

```
能用          → 硬编码（进引擎的 9 个内置节点）
不能用（领域特有） → Skill（可插拔注册）
```

### 6.5 节点依赖规则

节点不能依赖具体实现，只能依赖接口：

| 依赖方式 | 例子 | 允许？ | 说明 |
|---------|------|--------|------|
| 依赖上下文接口 | `context.llm.call()` | ✅ | 可替换、可 mock |
| 依赖类型定义 | `import type { WorldSeed }` | ✅ | 只引类型，不引实现 |
| 依赖具体服务 | `import { seedRepo }` | ❌ | 紧耦合，无法替换 |
| 依赖上一步输出 | `inputs.seed` | ✅ | 数据流，不是代码依赖 |
| 依赖配置参数 | `config.skillId` | ✅ | 配置注入，非硬编码 |

节点自身的职责：
1. 声明自己需要什么（inputs / config）
2. 从 context 获取能力
3. 执行逻辑
4. 产出 outputs

不做的事：
1. ❌ 不 import 任何业务服务
2. ❌ 不直接读写数据库
3. ❌ 不操作文件系统
