# Novel Wizard 深度分析 — Ver.0.1.0 重构线

## 一、项目定位

AI 小说创作系统，核心理念为「可生长的故事世界操作系统」：从灵感种子（Seed）出发，通过迭代演化构建故事世界，区别于「一键成书」生成器。

## 二、技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 前端框架 | Vue 3 (Composition API) + Vite | SFC + TypeScript |
| UI 库 | Naive UI | 企业级 Vue 3 组件库 |
| 路由 | vue-router 4 | 14 侧栏路由 + PlaceholderView 占位策略 |
| 后端 | Express (Node.js) | 模块化路由注册 |
| 数据库 | SQLite (sql.js) | WAL 模式，运行时嵌入 |
| 工作区 | npm workspaces | monorepo 管理 |
| 测试 | Vitest + Supertest | 包级单元测试 + API 集成测试 |
| 类型系统 | TypeScript + Zod | 运行时 schema 校验 + normalize |
| 构建 | esbuild + rollup + vue-tsc | Vite 驱动 |

## 四、数据库模型（SQLite schema v1.0.3）

### 4.1 核心表

| 表 | 用途 | 关键字段 |
|----|------|----------|
| **seeds** | 世界种子全局快照 | title, genre, tone, protagonist, setting, conflict, themes[], world_rules[], locations[], characters[], fragments[] |
| **sessions** | 灵感会话容器 | title, project_id (FK) |
| **versions** | 会话内版本链 | session_id, parent_id, seed_id (FK), version_tag, raw_input, title 等 |
| **session_state** | 会话 UI 状态持久化 | scope_key, chat_turns JSON, skill_results JSON, completeness, doc_raw_input |
| **projects** | 书架项目 | title, creator_type (ai_writer/ai_assisted), drive_type, work_length, ownership |
| **project_sections** | 项目板块（树形结构） | project_id, section_type, title, content JSON, sort_order, parent_id |
| **project_entities** | 实体解析（角色/地点） | entity_type, name, relations[], link_mode, status |
| **tags** | 标签云 | name, category, group_name, description |
| **embeddings** | 标签向量 | source_type, source_id, vector JSON |
| **guild_writers** | 作家协会 AI 作家 | name, model, temperature, top_p, max_tokens, style, behavior |
| **vocab** | 词库 | word, category, meaning |
| **roadmap_items** | 开发路线图 | phase, title, status |
| **notes** | 便签云 | content, color |

### 4.2 外键关系

```
projects
  └─ project_sections (CASCADE)
  └─ project_entities (CASCADE)
sessions
  └─ versions (seed_id → seeds, parent_id → versions)
  └─ session_state (version_id → versions, CASCADE)
```

## 七、Agent 编排架构（核心设计亮点）

### 7.1 回合流转路由图

声明式编排，5 节点顺序路由，首个命中即返回：

```
order 0:  fixed:delegate        ← 硬编码：委托给其他 Agent
order 10: fixed:flow-continue   ← 硬编码：flowNext 续接
order 20: fixed:skill-select    ← 硬编码：Skill 选取（gate: skill-select）
order 30: model:route           ← LLM 调度（gates: skill-select + flow-model-route）
order 40: fallback:chat         ← 回落：纯聊天
```

### 7.2 三种驱动类型

| 驱动 | 用途 | 示例 |
|------|------|------|
| hardcoded | 规则锁定，确定性的 | 委托、flowNext、固定 Skill |
| llm | 模型调度 | 识别用户意图、选 Skill |
| fallback | 策略链回落 | 兜底纯聊天 |

### 7.3 运行时管线步骤

```
user input
  → skill-select（预处理斜杠命令/Skill 匹配）
  → flow-model-route（LLM 路由决策）
  → knowledge-retrieve（知识检索）
  → document-load（Skill 文档挂载）
  → chat（LLM 对话调用）
  → validate（输出校验）
```

### 7.4 三种对话管线

| 管线 | 用途 |
|------|------|
| dispatchWorkshopTurn | 工坊主通道：Skill+Chat+委托 |
| sendDevTestAgentMessage | 开发者测试 Agent |
| runBlankShellTurn | 壳层桩（走通 UI 流程） |

## 八、Skill 系统

### 8.1 架构分层

| 层 | 职责 |
|----|------|
| catalog | 22 项 Skill SSOT · runtimeTier 波次 |
| skill-select | 3 种选择策略（关键词/slash/chat回落）+ 注册表 |
| turn-flow | 回合流转决策（resolveTurnFlow） |
| orchestrator | 声明式路由图引擎（runTurnRoutingOrchestrator） |
| document | 动态 Skill 文档挂载（Agent 注入全文） |
| composite | 复合 Skill（开书三基座） |

### 8.2 执行通道

```
skill-run      → POST /api/skills/run（标准管线）
dedicated-api  → 独立路由（storyteller 等）
planned        → 仅 catalog 展示
document       → Agent 动态挂载，不走 API
```

### 8.3 Skill 选择策略

1. **斜杠命令**（/parse, /expand 等）
2. **关键词匹配**（catalog keyword strategy）
3. **LLM 调度**（model router）
4. **chat 回落**（默认对话）

## 九、硅灵反射协议（Silicon Reflection）

规划器(Planner) ↔ 执行器(Executor) 之间的方法调用协议：

```
┌─────────────────┐      encode()      ┌─────────────────┐
│    Planner      │ ──────────────────→ │    Executor     │
│  (生成计划)      │   MethodCall JSON    │  (执行步骤)      │
│                 │ ←────────────────── │                 │
└─────────────────┘      parse()        └─────────────────┘
```

- IO profiles 定义输入/输出 schema
- Registry 管理可调用的方法
- 支持嵌套调用和异步执行

## 十、零记忆协议（Zero Memory）

统一的知识/书架/档案/文档获取协议：

```
Unified Request
  → sources（数据源适配器）
    → extract（提取）
      → format（格式化输出）
```

## 十二、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| DB 运行时 | SQLite (sql.js) 嵌入 | 无需外部数据库服务，原型阶段敏捷 |
| 模块化路由 | env 控制挂载 | 按需启用 API 模块，便于开发和测试 |
| 编排层 | 声明式路由图 | 将路由逻辑从代码提升为可观测/可编辑的图 |
| Skill 系统 | 双通道（API + 文档挂载） | 适应不同的 Skill 复杂度 |
| 硅灵反射 | 规划器-执行器分离 | Agent 自主性与可观测性的平衡 |
| 版本链 | 父子版本 + 种子快照 | 支持回溯/分支/合并的创作流程 |
| monorepo | npm workspaces | 包间依赖清晰，发布前无需工具链 |
| 测试策略 | 包级单元测试 + 集成测试 | 分层验证，API 级测试保证契约 |
